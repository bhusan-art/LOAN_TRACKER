# 03 — Data model

`ledger_entry` is the source of truth. `due` and `allocation` are written by the engine, never by hand.

| Table | Key fields | Notes |
|---|---|---|
| party | id, name, phone, address, id_proof_ref, guarantor, notes, risk_tag, created_at | Anyone the owner lends to or borrows from; can be on both sides |
| loan | id, party_id, direction (GIVEN/TAKEN), book (BUSINESS/PERSONAL), principal_paise, start_date, rate, rate_unit (PER_MONTH/PER_YEAR), interest_type (SIMPLE/COMPOUND/EMI), interest_cycle (MONTHLY/QUARTERLY/AT_MATURITY), due_day, grace_days, penalty_rule, tenure_months, maturity_date, collateral, purpose, status, created_at | The agreement. Changed only via adjustment entries (RATE_CHANGE etc.) |
| ledger_entry | id, loan_id, entry_date, type, amount_paise, payment_mode (CASH/UPI/BANK), reference, note, created_at, reversed_by_id | Types: DISBURSE, TOPUP, PAYMENT, PRINCIPAL_PREPAY, WAIVER, PENALTY, RATE_CHANGE, CAPITALISE, REVERSAL. Append-only |
| allocation | id, ledger_entry_id, due_id (nullable), bucket (PENALTY/INTEREST/PRINCIPAL), amount_paise | How each payment was split |
| due | id, loan_id, period_start, period_end, due_date, interest_paise, paid_paise, status (UPCOMING/PARTIAL/PAID/OVERDUE/WAIVED) | One row per interest cycle, generated by daily job |
| funding_link | id, taken_loan_id, given_loan_id, amount_paise, link_date | Which borrowed money funded which given loan. Many-to-many. Unlinked part of a GIVEN loan = own capital |
| reminder_log | id, due_id, kind, channel, sent_at | Prevents duplicate reminders |

Optional later: audit_log (when second user exists), attachment (promissory notes, cheque photos).
Indexes: ledger_entry(loan_id, entry_date), due(due_date, status), loan(book, direction, status).

## Business vs personal books
- `book` is required on every loan. Moving a loan between books = logged adjustment, never a silent edit.
- Entries, dues, allocations inherit the book of their loan (no book column on them).
- UI toggle: All (default, consolidated) / Business / Personal. Remembered per device, shown as a coloured badge.
- Cross-book funding: a funding_link may join a TAKEN loan in one book to a GIVEN loan in the other.
  Allowed, but flagged with a warning badge and listed in a "Cross-book funding" report.
- Reports per book: interest earned, interest paid, net interest income per financial year (Apr-Mar).
  Kept separate because business and personal interest are typically taxed differently (confirm with a CA).
- Notifications tagged [BIZ] / [PER]. One book's reminders can be muted, except payables overdue.
- Later: business-only expense ledger (agent fees, legal costs).
